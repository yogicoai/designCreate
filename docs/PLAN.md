# imgCreate — 자사몰 이미지 생성 프로그램

MD·마케터가 **전속 모델 + 제품·컬러 + 포즈/스타일 레퍼런스**를 골라
나노바나나(Gemini image)로 자사몰 썸네일·이벤트 배너를 직접 생성·관리하는 웹앱.

- 스택: Next.js 16 (App Router, TS) · MongoDB(Atlas) · Cafe24 FTP · Gemini Image
- 배포: Vercel · 로컬 dev 포트 6100

---

## 1. 왜 만드나 — 메우려는 갭

품질이 실제로 나오는 워크플로우(**눌림레퍼 + 제품 색상락 + 모델 표정시트**를 동시에 넣는
다중 참조 합성)는 지금 **Claude Code 세션에서 사람이 Higgsfield를 수동으로** 돌린다.
`Desktop/youtube/src/app/api/../GeneratedImage.ts` 주석에도 `Higgsfield 생성 — 외부 도구,
서버에서 호출 불가`로 박혀 있다. 그래서 MD·마케터가 스스로 못 쓴다.

나노바나나는 **다중 참조 이미지 합성 + 인물 아이덴티티 유지**가 강점이라 이 갭에 정확히 맞고,
서버에서 REST로 호출되므로 웹앱화가 가능하다.

## 2. 핵심 생성 플로우

MD 화면에서 아래를 고르면 프롬프트 조립기가 영문 프롬프트 + 참조 이미지 N장을 구성한다.

1. **베이스** — ① 기존 승인 컷(151개) 또는 ② 실사 포즈 레퍼(`off`=형태 / `on`=포즈·각도)
2. **모델** — 여성 A~D · 남성 A · 아동 A~B + 표정 패널(expr 시트) + 의상 코드
3. **제품·컬러** — 제품 레지스트리 70종, 공식 컬러칩 hex + 컬러 스와치 자동 첨부
4. **방향 지시** — 한글 자유 입력 ("배경 거실로", "랩탑 들고")
5. **규격** — 1:1 리스트 / 4:5 상세 / 16:9 배너 / 9:16 릴스

→ Gemini 호출 → 2샘플 → 선택 → FTP 업로드 → DB 등록

> `thumb_review_2026-08-23.md` 실측: "생성본을 베이스로 한 포토에딧이 컬러 리컬러 +
> 인물 2명 교체까지 안정적으로 동작 — 앵글·제품 형태가 확정된 컷은 이 방식이 가장 빠름."
> 즉 **베이스 컷 기반 포토에딧**이 1순위 경로이고, 0-from-scratch는 2순위다.

## 3. 이관할 자산 (전부 cafe24 공개 URL — 재업로드 불필요)

`Desktop/youtube` 의 하드코딩 상수 + JSON 을 파싱해 Mongo 로 시드한다.

| 자산 | 수량 | 출처 |
|---|---|---|
| 제품 레지스트리(기하·치수·컬러 hex·360뷰 8각도) | 70종 | `data/products.json` |
| 공식 컬러칩 | — | `data/colorchips.json` |
| 제품 라인 / 컬러 슬롯 | 11 / 57 | `app/thumbnails/page.js` |
| 기존 생성 컷 (spec 문자열에 레시피 인코딩됨) | 151 | 〃 |
| 실사 포즈 레퍼 (on=포즈각도 / off=형태) | 52 | 〃 |
| 전속 모델 + 아이덴티티 시트 4종 | 7명 | `app/models/page.js` |
| 생성 주의사항 체크리스트 | 10 | 〃 |

`spec` 예: `'B · 포즈4 정면(플랫라운저·확대) · 미소 · 색보정 · #f2f2f4'`
→ 모델코드 · 포즈 · 표정 · 의상코드 · 배경을 파싱해 **레시피로 재사용**한다.

## 4. 프롬프트 조립 — 그대로 계승할 규칙

`youtube/src/lib/productPrompt.js` 의 **12차 실측 4종 세트**는 코드로 이식한다.

1. 카테고리 단어 금지 → **기하 서술** (맥스를 "beanbag"이라 하면 둥근 공으로 그려짐)
2. **실측 치수** 명시
3. **NOT 네거티브**
4. **인체 대비 스케일 앵커** (모델은 cm를 못 읽는다)

여기에 `eventTemp/src/lib/generated-image-prompt.ts` 의 **텍스트 세이프존 + 텍스트 전면 금지**를
배너 모드에 결합한다. (한글 카피는 배너 에디터에서 얹는다)

그리고 `thumbnails/page.js` 의 CAUTIONS 10개를 시스템 규칙으로 상수화:
자연스러운 미소 기본 · 배경 `#f2f2f4` · 지퍼/봉제선 금지 · expr 시트 동반 투입 · 2048 무손실 등.

## 5. 검증된 구현 참고

`Desktop/Dong/src/lib/gemini.ts` — 실전 다듬어진 Gemini 이미지 클라이언트. 그대로 참고:

- REST `v1beta/models/{model}:generateContent`, `responseModalities:["TEXT","IMAGE"]`, `imageConfig.aspectRatio`
- 다중 참조 = `inlineData` 파트 배열 + 마지막에 text 프롬프트
- 429 세분화(**분당 몰림 vs 일일 소진**) + 백오프 재시도
- `promptFeedback.blockReason` — **아동 안전필터 실제 발생**
- `shrinkForReference` — 참조를 1024px JPEG로 축소 (**아래 6-① 사고 대응**)

## 6. 알려진 제약 — 설계에 미리 반영

① **Vercel 요청 본문 4.5MB 한도.** Dong에서 실제 사고(2026-08-29): 참조 2장이 4.5MB를 넘겨
   해당 페이지가 통째로 실패. 우리는 참조를 3~5장 넣으므로 **`shrinkForReference` 필수**.

② **함수 실행시간.** Pro 2K 생성은 flash보다 느리다(수십 초). Vercel 플랜별 상한 확인 필요 → 초과 시 잡 큐 방식으로 전환.

③ **컬러 정확도.** 공식 hex 재현은 모든 모델이 약함. 대응 = 컬러 스와치 PNG 참조 동반 투입
   (기존 팀이 쓰던 방법) + 생성 후 Lab 보정. `thumb_review` 에 "v2 컬러 Lab 매칭 보정" 기록 있음.

④ **아동 컷 안전필터.** Higgsfield에서 아동 컷 nsfw 거부 기록 있음. Gemini도 동일 위험 → 실측 필요.

⑤ **Element 토큰 상실.** Higgsfield 제품 락은 대응물이 없음. 베이스 컷 방식이면 영향 작지만,
   0-from-scratch 신규 구도에서는 아쉬움 → 생성부를 **어댑터 구조**로 짜서 나중에 라우팅 가능하게.

⑥ **SynthID.** Gemini 생성물에 비가시 워터마크 포함. 상업 사용엔 무방.

## 7. 단계

- **Phase 0** — 스캐폴드 · env · Gemini 연결 점검 ✅
- **Phase 0.5** — **A/B 실측**: 기존 승인 컷 3~5개를 나노바나나로 재현해 나란히 비교.
  "퀄리티 괜찮은가"를 추측이 아니라 결과로 판정한다. 아동 컷 필터도 여기서 확인.
- **Phase 1** — 자산 이관: 시드 스크립트 + Mongo 스키마 + 관리 UI(제품·모델·레퍼런스·컬러)
- **Phase 2** — 프롬프트 조립기 (4종 세트 + CAUTIONS + 레시피 파서)
- **Phase 3** — 생성 파이프라인 (Gemini 어댑터 · 참조 축소 · 2샘플 · FTP 업로드 · 이력 DB)
- **Phase 4** — 배너 모드 (텍스트 세이프존 · 사이즈 프리셋)
- **Phase 5** — Vercel 배포 · 사용량 한도 · 접근 권한
